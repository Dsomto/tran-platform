The story you are grading

An attacker known as The Griot breached Sankofa Digital, a 600-person Nigerian fintech. Forty-eight hours after the breach was contained, the threat-intel lead Tunde pulled a zip of files off a staging server the Griot abandoned. This chapter, your interns worked through that drop: they cracked the codes, broke apart a captured login token, sorted the password hashes, and pulled apart an encrypted note.

Two people receive their work in-story: Amaka Eze (Head of Security — the CSO) and Dr. Folake Bello (external cryptography consultant). The recurring lesson the whole chapter teaches is one line: the algorithm is not the asset — the key is. The Griot used modern encryption and still got caught out, because keys, tokens and secrets were left lying in config files and logs.

You are grading the write-up of all that — the in-platform write-ups plus the capstone report addressed to the board.

How scoring works

A Stage 1 final mark is out of 100, from two inputs:

REPORT — what YOU grade — 80%
TERMINAL — 20%

You grade the report: one holistic score 0–100 plus feedback, entered on the grading form (there are no per-item boxes — the weights below are your worksheet to reach the one number). The report = the four in-platform write-ups and the capstone folder, judged together.

The platform grades the terminal tasks automatically — the six flag / multiple-choice puzzles (tasks 1, 2, 4, 5, 8, 9). You never touch them, so their answers are not in this guide; they are simply the 20%.

Hashes in the Breach File

16

What it asks: identify four password hashes, rank rotation urgency, name the one that's fine, cite 2+ real sources.

Answer key
Abcrypt cost 12 — marker $2b$12$ — fine
BMD5 — bare 32-hex (it's MD5 of "password") — rotate FIRST
CSHA-256 — bare 64-hex (SHA-256 of "password") — rotate second

Key insight: the modern, slow hashes (bcrypt, Argon2id) are the safe ones; the old unsalted ones (MD5, raw SHA-256) crack in seconds against a rainbow table / GPU. Correct order: B then C.

Task 7 · write-up

The Accepted Token (JWT)

16

What it asks: decode a captured login token, name the root cause precisely, name the server's failure, propose the fix.

Answer key Header {"alg":"none","typ":"JWT"} · Payload {"sub":"admin","role":"super_admin","iat":1700000000} · signature empty.
Root cause: the server accepted alg:none — a token with no signature treated as valid (CVE-2015-9235). Server failure: no explicit algorithm allow-list. Fix: (1) allow-list HS256/RS256, never none; (2) never trust the role claim from the token — authorise server-side.
The trap: "don't trust the role claim" is a problem but not the root cause — a validly signed token still carries it. The root cause is alg:none acceptance.

Task 10 · write-up

Brief the Board

16

What it asks: a 250+ word board-facing note for a CFO, answering three questions, with 3+ real citations and an evidence appendix. Read it once as a board member: could a non-technical executive act on it?

Answer key — the three required answers Q1 — what confidentiality alone did NOT give Sankofa: encryption ≠ integrity / authentication / key-protection. Must cite one specific lab mistake (AES-GCM key in config.env, base64 API key, the alg:none JWT, or the lone MD5). Headline: the algorithm is not the asset; the key is.

Q2 — why a hash alone can't detect tampering: an attacker who owns storage swaps file + hash together → you need an HMAC (secret) or a digital signature (public key); the verifier holds a key the attacker doesn't.

Q3 — one audit pattern: exactly one, evidenced — e.g. "audit every config and log for plaintext secrets," backed by config.env + .creds.bak. A laundry list fails.

Writing the feedback

Feedback is required with the score. The intern reads it on their dashboard and in their result email, pass or fail. Aim for 3–5 sentences: one real strength, the biggest weakness, and what to do differently — tone matching the score.

Strong report (≈ 84)"Really solid. D1 tied every failure to its file and a real standard (FIPS 197 for AES, RFC 7519 for the JWT), and Task 7 correctly named the root cause as alg:none acceptance — most miss that. Weakest point: D3's KMS control maps to only one D1 failure, so it reads generic. Tie it to two and this is board-ready."
Mixed report (≈ 61)"You decoded artefacts B and C and ranked MD5 first — both right. But Task 3 invented a plaintext for Artefact A, which is an unsolvable distractor, so that's fabrication, not a recovery. D2 pasted plaintexts with no method or intermediate steps, so I couldn't see your working. Show the steps and don't force unsolvable artefacts."
Weak report (≈ 38)"This didn't meet the bar. D1 listed failures but cited no files and no standards, so each finding scores zero on the evidence rule. The JWT write-up said the signature was 'weak' — there was no signature; alg:none was accepted. D4 reads as generic prose with no personal stance. Re-read the brief's citation requirement before the next stage."

Don't write: "Good job!" · "Needs improvement." · just a number. The intern can't act on any of those.
